Read your company's calls from your CRM

The Callit API gives your CRM every company-SIM call your employees make or receive, with the comment, outcome, follow-up date and recording, plus the same reports the Callit panel shows. It follows Callyzer's API v2.3, so a CRM already built for Callyzer only needs a new base URL and key.

Base URL
https://callit.reaplift.com/api/v2.3/
Authentication
Authorization: Bearer <key>
Format
JSON in, JSON out
Rate limit
5 requests a second per key

Getting started

  1. Log in to the Callit panel at https://callit.reaplift.com as your company's admin.
  2. Open Settings, scroll to API keys for your CRM, type a name such as "Our CRM" and press Create key.
  3. Copy the key straight away. It starts with rlk_ and is shown only once. If it is lost, revoke it and create another.
  4. Save it in your CRM's server settings (for example Laravel's .env). Call the API only from your server, never from a web page, so the key never reaches a browser.

A key reads one company's calls: the company of the admin who created it. Revoking a key in Settings stops it at once.

Try it
curl -X POST https://callit.reaplift.com/api/v2.3/call-log/summary \
  -H "Authorization: Bearer $CALLIT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"call_from": 1794441600, "call_to": 1794527999}'

Moving from Callyzer

Paths, request fields and answer fields are Callyzer v2.3's. Change these two things in your CRM:

CallyzerCallit
Base URLhttps://api1.callyzer.co/api/v2.3/https://callit.reaplift.com/api/v2.3/
KeyCallyzer dashboardCallit panel, Settings

Where Callit behaves differently:

  • Recording links work for 24 hours. Callyzer's links look permanent. Don't store call_recording_url; ask for the call again (calls by ID) to get a fresh link. Recordings are kept for 12 months.
  • Phone calls only. call_method and call_mode are optional. WhatsAppCall or Video return no calls.
  • Employee tags are Callit team names. Teams are set up in the panel.
  • No leads. lead_id is always empty and the lead/* endpoints don't exist; leads stay in your CRM.
  • Not available yet: deleting a recording through the API, and webhooks. Until webhooks arrive, poll history with synced_from/synced_to to pick up new calls.
  • Faster limit: 5 requests a second per key, against Callyzer's one every 2 seconds.

Filters

Every call-log/* endpoint takes these fields in its JSON body. Leave out a field, or send it empty or null, to skip it.

FieldTypeMeaning
call_from, call_toUnix secondsCalls that started in this range, both ends included. Send both. Without any dates you get today, India time.
synced_from, synced_toUnix secondsCalls that reached Callit in this range. Use these to fetch only new calls.
A range can be at most 180 days.
call_typesstring[]Incoming, Outgoing, Missed, Rejected
duration_grt_than, duration_les_thansecondsTalk time more than / less than (the bound itself is not included)
ringing_time_grt_than, ringing_time_les_thansecondsRinging time more than / less than
emp_numbersstring[]Employees' company SIM numbers: 91-9876500000, 9876500000 and 919876500000 all work. A number Callit doesn't know is an error.
emp_tagsstring[]Team names
client_numbersstring[]The other person's numbers, any format
is_exclude_numbersbooleanDefault true: leaves out the numbers your admin marked as excluded (office lines, colleagues)
call_method, call_modestringOptional. PhoneCall and Voice match every call.
page_no, page_sizeintegerLists only. Defaults 1 and 100; page_size from 1 to 100.

Answers and errors

Every answer has result and message. Lists also carry total_records, page_no and page_size.

{ "result": [ ... ], "message": "Success", "total_records": 215, "page_no": 1, "page_size": 100 }

An error has "result": null and a message that says what to fix:

StatusWhenExample message
400A field is wrongInvalid call_types. Valid call types are Incoming or Outgoing or Missed or Rejected.
401Missing, wrong or revoked keyInvalid API key
403Your company's Callit account is suspendedYour company is suspended
429More than 5 requests in a second. Wait for the Retry-After header (1 second) and try again.Too many requests: at most 5 a second for each key
500Our fault; try again shortlySomething went wrong. Please try again.

POSTcall-log/get

Up to 20 calls by their id. Use it to refresh a recording link.

{ "unique_ids": ["1042", "1043"] }

The answer's result is a list of calls, as in history. IDs that don't belong to your company are left out.

POSTcall-log/history/stream

Every call in a range as one long answer, for a first import. call_from and call_to are required; other filters work, paging doesn't. The answer is NDJSON (Content-Type: application/x-ndjson): one call per line, then a last line that says how many were sent. Read until that line. At most 100,000 calls per request.

{"result": {"id": "1042", "emp_name": "Meena Iyer", "client_number": "9900011111", ...}}
{"result": {"id": "1041", ...}}
{"type": "END", "total_records": 2, "message": "Success"}

Reports

Reports take the same filters and count calls the same way the Callit panel does. "Connected" means the other side answered and talk time is more than zero.

POSTcall-log/summary

Totals for the period.

{
  "result": {
    "total_incoming_calls": 111, "total_incoming_duration": 11905,
    "total_outgoing_calls": 67,  "total_outgoing_duration": 4806,
    "total_missed_calls": 36,    "total_rejected_calls": 1,
    "total_calls": 215,          "total_duration": 17617,
    "total_never_attended_calls": 16,
    "total_not_pickup_by_clients_calls": 8,
    "total_unique_clients": 48,
    "total_working_hours": "100:19:34",
    "total_idle_time": "95:23:33",
    "total_connected_calls": 139
  },
  "message": "Success"
}

Durations are in seconds. total_working_hours adds up, for each employee and day, the time from their first call's start to their last call's end. total_idle_time is that minus the time spent ringing and talking. Both are HH:mm:ss, and hours can pass 24 over several days or employees.

POSTcall-log/employee-summary

The summary per employee, busiest first, paged. Every active employee is listed, including those with no calls. Each entry has the employee fields, the summary totals plus total_incoming_connected_calls and total_outgoing_connected_calls, the averages avg_duration_per_call, avg_incoming_duration and avg_outgoing_duration (HH:mm:ss), and last_call_log (their latest call in the period, or null).

{
  "result": { "employees": [
    { "emp_name": "Meena Iyer", "emp_code": "CR-7", "emp_country_code": "91", "emp_number": "9876500000",
      "emp_tags": ["North"], "total_calls": 5, "total_duration": 245, "total_connected_calls": 2,
      "total_never_attended_calls": 1, "total_working_hours": "05:00:30", "avg_duration_per_call": "00:00:49",
      "last_call_log": { "id": "1046", "client_number": "9900044444", "call_type": "Outgoing", ... }, ... }
  ] },
  "message": "Success", "total_records": 2, "page_no": 1, "page_size": 100
}

POSTcall-log/analysis

Averages and the standout employees: average_duration (seconds per call, per day with calls, per incoming and outgoing call), time_analysis (average working and idle time per employee per day), top_dialer (most outgoing calls), top_answered (most answered incoming calls), top_caller (most calls), highest_total_duration, and longest_duration with the longest call in longest_duration.call_log. Any of these is null when there are no calls.

POSTcall-log/never-attended

Missed or rejected calls from people nobody spoke to afterwards in the period: the callers still waiting for a call back. Grouped by employee and client, paged by group.

{
  "result": [
    { "emp_name": "Meena Iyer", "emp_number": "9876500000", "emp_tags": ["North"], ...,
      "client_name": "", "client_country_code": "91", "client_number": "9900033333",
      "call_logs": [ { "id": "1045", "duration": 0, "call_type": "Missed", "call_date": "2026-11-12",
                       "call_time": "13:00:00", "ringing_time": 15, ... } ] }
  ],
  "message": "Success", "total_records": 1, "page_no": 1, "page_size": 100
}

POSTcall-log/not-pickup-by-client

Outgoing calls nobody answered, to people nobody spoke to afterwards in the period. Same shape as never attended.

POSTcall-log/unique-clients

One entry per outside number, most recent first, paged: client_name, client_country_code, client_number, the call totals (total_calls, total_duration, incoming, outgoing, missed, rejected, connected, never attended, not picked up), and last_call_log with the employee who had that call.

POSTcall-log/hourly-analytics

Calls, connected calls and talk time per hour, India time. Optional extra fields: working_hour_from and working_hour_to (HH:mm, 24-hour, counted in whole hours) add "Before" and "After" slots around the working hours; exclude_days (Sun…Sat) leaves days out. Without working hours you get 24 one-hour slots.

{
  "result": {
    "total_calls": 5, "total_connected_calls": 2, "total_duration": 245,
    "daily_average": { "avg_calls": 5, "avg_connected_calls": 2, "avg_duration": 245 },
    "time_slots": [
      { "slot": "Before 10:00 AM", "total_calls": 1, "total_duration": 0, "total_connected_calls": 0,
        "total_call_perc": 20, "total_duration_perc": 0, "total_connected_calls_perc": 0 },
      { "slot": "10:00 AM - 10:59 AM", ... },
      { "slot": "After 02:00 PM", ... }
    ]
  },
  "message": "Success"
}

POSTcall-log/daywise-analytics

The same slots, each broken down by date (day_wise: date, day, totals and percentages), with how many days each slot had no calls (days_with_no_calls_in_time_slot).

Employees

GETemployee/get

Your active employees and the state of their phone. Filters, all optional: emp_numbers, emp_tags, emp_codes, emp_name (exact, any case), page_no, page_size. Send them as a query string (lists as a,b), or use POST with a JSON body.

{
  "result": [
    { "emp_name": "Meena Iyer", "emp_code": "CR-7", "emp_country_code": "91", "emp_number": "9876500000",
      "emp_tags": ["North"], "app_version": "0.5.0",
      "registered_at": "2026-11-11 10:12:00 IST", "modified_at": "2026-11-11 10:12:00 IST",
      "last_call_at": "2026-11-12 15:00:00 IST", "last_sync_req_at": "2026-11-12 15:01:10 IST",
      "is_lead_active": false, "is_call_recording_active": true,
      "device_details": { "device_model": "vivo I2221", "version_code": "0.5.0", "board": "",
                          "android_version": "16", "sdk_version": "36", "unique_sim_id": "…" },
      "device_preference": { "is_app_uninstalled": false, "battery_percentage": null },
      "app_settings": { "default_home_screen": "Call history", "note_dialog": true,
                        "call_recording_location": "", "is_log_active": true } }
  ],
  "message": "Success", "total_records": 1, "page_no": 1, "page_size": 100
}

is_app_uninstalled is true when the employee has no paired phone. is_call_recording_active is true when a recording arrived in the last 7 days. battery_percentage is null for now.

PHP example

For a Laravel CRM, with the key in .env as CALLIT_API_KEY. This fetches yesterday's calls page by page.

use Illuminate\Support\Facades\Http;

$from = now('Asia/Kolkata')->subDay()->startOfDay()->timestamp;
$to   = now('Asia/Kolkata')->subDay()->endOfDay()->timestamp;
$page = 1;

do {
    $response = Http::withToken(env('CALLIT_API_KEY'))
        ->acceptJson()
        ->retry(3, 1000, fn ($e) => optional($e->response)->status() === 429)
        ->post('https://callit.reaplift.com/api/v2.3/call-log/history', [
            'call_from' => $from,
            'call_to'   => $to,
            'page_no'   => $page,
            'page_size' => 100,
        ]);

    if ($response->failed()) {
        throw new RuntimeException('Callit: ' . $response->json('message'));
    }

    foreach ($response->json('result') as $call) {
        // $call['client_number'], $call['call_type'], $call['duration'], $call['note'], ...
    }

    $page++;
} while (($page - 1) * 100 < $response->json('total_records'));

Field reference

FieldMeaning
idCallit's call ID, a string of digits. Stable: use it to avoid saving a call twice.
emp_name, emp_codeThe employee's name and code, as entered in the panel
emp_country_code, emp_numberThe employee's company SIM, split: 91 and 9876500000
emp_tagsThe employee's team names
client_nameThe contact name saved on the employee's phone, Private number for a hidden caller, or empty
client_country_code, client_numberThe other person's number, split the same way. A number outside India keeps all its digits and an empty code.
durationTalk time in seconds
call_typeIncoming, Outgoing, Missed or Rejected
call_date, call_timeWhen the call started, India time (yyyy-mm-dd, HH:mm:ss)
ringing_timeSeconds of ringing before it was answered or ended
noteThe employee's comment from the after-call pop-up
crm_statusThe outcome the employee picked, for example Interested. Your admin sets the list in Settings.
reminder_date, reminder_timeThe follow-up date the employee set, India time
call_recording_urlA link to the recording that works for 24 hours, or null when there is no recording
synced_atWhen the call reached Callit, yyyy-mm-dd HH:mm:ss IST
modified_atLast change, for example when the comment arrived
lead_idAlways empty
call_method, call_modeAlways PhoneCall and Voice

Only calls on employees' company SIMs reach Callit. Calls on a personal SIM never leave the phone, so they are never in the API.
